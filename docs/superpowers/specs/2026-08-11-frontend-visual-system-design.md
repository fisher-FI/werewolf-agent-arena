# AI 狼人杀前端视觉系统设计

## 目标

将现有前端统一为轻量的 AI 狼人杀观战工具。界面重点是“谁说了什么、谁投了谁、局势如何变化”，而不是赛事后台、AI 实验室或营销页面。

## 设计方向

- 核心隐喻：观战牌桌。
- 主色基底：深灰近黑，降低长时间观战疲劳。
- 状态色：暖金表示当前阶段与焦点，红色表示狼人/淘汰，蓝色表示好人，紫色表示神职。
- 颜色只作为辅助，所有状态同时使用文字、位置或图标表达。
- 统一使用简短中文标签，避免大段说明和装饰性文案。
- 卡片保持低圆角、细边框和紧凑间距，避免卡片嵌套。

## 页面结构

### 大厅

- 顶部品牌、导航和设置入口。
- 主区域按“选择板子 -> 创建房间 -> 继续观战”组织。
- 板子选择使用等宽选择项，选中状态使用暖金边线。
- 房间列表只显示房间编号、板子、状态和人数。
- 空状态提供明确的创建房间主操作，不显示营销型 Hero。

### 对局观战页

- 顶部操作栏：品牌、暂停/继续、返回大厅。
- 阶段栏：当前天数、白天/夜晚阶段、当前发言者。
- 主体为三列：左侧 1-6 号席位，中间对局时间线，右侧 7-12 号席位。
- 玩家席位固定编号，展示名字、模型、存活状态；当前发言者使用暖金边线和“发言中”文字。
- 中间默认展示“发言与行动”，包括公开发言、投票、死亡、阶段变化和当前生成状态。
- “AI 推理”作为同级标签页，默认不与公开发言混排；推理内容保留 reasoning 与 speech 的层级区分。
- 选中玩家后在底部显示详情条；身份信息遵循当前后端的公开/结束后可见规则。
- 游戏结束状态显示胜方、结束原因和身份揭示，不改变主要页面骨架。

### 设置页

- 保留模型预设、模型连接表单、温度、最大输出长度和人格 Prompt。
- 使用单列主表单和紧凑的预设选择区，减少大面积卡片。
- 保存、错误、成功状态在表单底部就地反馈。
- API Key 始终使用密码输入，不回显后端已保存的值。

## 组件边界

- `AppShell`：全局导航、页面宽度和基础主题。
- `StatusButton`：主操作、次操作、暂停/继续等按钮的统一外观。
- `BoardPicker`：板子选择与选中状态。
- `RoomList`：房间状态列表与空状态。
- `SeatRail` / `SeatSlot`：两列玩家席位，处理存活、发言、选中和等待态。
- `PhaseBar`：阶段、天数、当前行动信息。
- `EventTimeline` / `EventItem`：事件分组、公开发言和行动结果。
- `ReasoningPanel`：推理记录、置信度和对应公开发言。
- `PlayerDetailBar`：选中玩家的底部详情。
- `AISettingsForm`：预设与 AI 配置编辑。

组件只负责展示和局部交互；房间数据、WebSocket 连接、创建/启动/暂停等副作用继续由页面层与现有 `api` 服务处理。

## 数据流与状态

- `Lobby` 通过现有 `api.listRooms()`、`api.listBoards()` 和 `api.createRoom()` 获取数据。
- `Room` 首次通过 `api.getRoom()` 加载，再通过现有 WebSocket 事件更新房间、事件、推理、阶段和游戏结束状态。
- 时间线按 `day_count + phase` 分组，事件按到达顺序追加，保留自动滚动行为。
- UI 不根据推理文本推断身份；身份展示只使用后端提供的角色字段和当前公开规则。
- API/WS 错误就地显示，不能让错误文本替代玩家发言或推理内容。

## 响应式行为

- 桌面宽度使用三列布局，席位列保持可扫描的固定密度。
- 小于约 720px 时，席位列折叠为可切换的“玩家”视图，时间线占据主区域；不允许横向溢出。
- 设置表单在窄屏变为单列，按钮与输入宽度适应容器。
- 所有文字、按钮和席位内容允许换行或省略，不能覆盖相邻内容。

## 可访问性与交互

- 席位、标签页、按钮和表单使用原生语义元素。
- 颜色状态同时配合文字标签，死亡席位不能只依赖降低透明度表达。
- 键盘可访问所有标签页、操作按钮和席位选择。
- 当前发言者、当前阶段和错误信息提供可读文本。

## 验证范围

- `npm run build`：检查 TypeScript 与 Vite 构建。
- `npm run lint`：检查 React/TypeScript 规范。
- 通过现有后端测试确认页面依赖的数据契约没有改变。
- 在桌面和窄屏尺寸检查大厅、对局、设置三页，重点观察两列席位、时间线滚动、标签页切换和文字溢出。

## 非目标

- 不新增用户登录、社交系统、排行榜、战绩中心或实时语音。
- 不改动狼人杀规则、AI 推理算法、后端 WebSocket 协议。
- 不将 AI reasoning 默认暴露到公开发言流。
